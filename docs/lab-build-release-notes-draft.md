# Release notes draft: the Lab assistant tool (`lab_build`)

Status: DRAFT for the release that ships the Lab screen and `lab_build` (branch `feat/lab-build`, built on `feat/studio-screen`). Nothing here has been applied: no version bump, no `readme.txt` edit, no zip rebuild. Applying it is the owner's step at release.

People read **Lab**. "Studio" is only the code name and must not appear in any text below.

## 1. Changelog wording (for `readme.txt`)

* New: Lab. A page builder screen in the plugin (the Lab tab) where you answer a few questions (what the page is for, the look, the sections, your words and pictures) and see a live preview, then save a draft page. The page is built from the plugin's proven section layouts, so it is checked before it is saved, like every other change.
* New: `lab_build`, the tool that lets your AI assistant use Lab. It can read a Lab brief you started and fill in the words (it is told which parts are still empty and never overwrites what you changed in the meantime), or build a whole page from a short brief and save it as a draft. The brief is much smaller than the Divi markup of the same page (measured for one six-section page in the token usage notes). Available over MCP and the REST API; it is always a draft.
* Improved: the Lab screen keeps your changes and your assistant's words apart. If your assistant fills in words while you have the screen open, nothing is lost: the screen merges them, or asks you to reload if the structure changed.
* Changed: 22 tools instead of 21 (`lab_build`).

The words "Lab" and "draft" are the user-facing terms. Do not claim the tool works with any named assistant until it has been tried with one (see section 4).

## 3. ChatGPT

* Claude, Cursor, VS Code Copilot and the other MCP clients, and ChatGPT's custom MCP connector, get the whole tool list from `tools/list`, so they are offered `lab_build` with no further step.
* The older custom GPT Action (the OpenAPI spec the plugin serves) does NOT get `lab_build`. The ChatGPT importer allows 30 operations and the 16 free plus 14 Pro operations already use all 30. `lab_build` is MCP and REST only, and `tests/LabBuildLockstepTest.php` pins that it is absent from the spec on purpose. This is the same as `html_to_divi`, `get_site_structure` and `get_custom_fields`.
* The readme sentence "(the older custom GPT Action offers most of them)" stays true.

## 4. Caveat: not confirmed with a real assistant account

What is proven: the tool is exercised through the real MCP route on a real Divi 5.15.1 site by a scripted client (`make verify-studio`, group I, 223 PASS 0 SKIP 0 FAIL), and the REST route and the MCP route run the same code (`LabBuildLockstepTest`). What is NOT proven: no real assistant (Claude, ChatGPT, Cursor ...) has used `lab_build` yet, so how well any model chooses the actions, fills the slots or reads the catalog is unknown. The words in the gate are the gate's own. Every public sentence should say the tool is new and that results with a given assistant have not been confirmed; do not name an assistant as working. The REST route is covered by the pure tests only, not by the live gate.

## 5. Limits to put in the support notes

* If a draft page is created but linking it to its brief fails, the tool does not report the page id, so a retry can make a second draft.
* The Lab screen can show a false "your assistant changed the brief" message after Create, in one rare race.
* A brief that names a recipe that has since been removed from the library makes `fill` answer 422 until the person fixes that section in the screen.
* A `fill` whose merged brief equals the stored one succeeds even with a stale hash (nothing is written, so nothing is lost).
* The screen's Create compares the brief hash before it compiles, not atomically with the save, so a write in that one compile window is not caught.
* The tool never overwrites a page that was edited in Divi, published or deleted: it makes a new draft and says why.
