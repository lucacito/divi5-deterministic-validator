# Pro Lab (`lab_restyle` and `build_site` briefs) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Two Pro features on top of the free Lab compiler: a 24th Pro tool `lab_restyle` that rebuilds unedited Lab pages in another design language and/or style kit exactly as Lab would build them, and a `brief` option on `build_site add_page` that builds a whole site from Lab briefs with one shared look, every page's brief stored in the free Lab store.

**Architecture:** Pro-only code in `pro-addon/src/Lab/*`, `pro-addon/src/Tools/LabRestyle.php` and `pro-addon/src/Kinds/LabBriefKind.php`; `BuildSite` gains one brief path. Both call the free `StudioCompiler`, `StudioBrief` and `StudioStore` public statics and write through the existing Pro machinery (`LayoutGate`, `HistoryService::write`, `PreviewToken`, `BatchLog`, `BatchUndo`). One read-only free addition, `StudioStore::linked()`. A per-tool guard (`LabSupport`) refuses only the Lab paths on a free plugin without Lab.

**Tech Stack:** PHP 8, PHPUnit (`make test`, `make test-pro` = `./vendor/bin/phpunit -c pro-addon/phpunit.xml`), the free test doubles `tests/FakeWpdb.php` (SQLite) and the Pro fixtures (`ThemeLayoutFixture`, `InMemoryBatchRepository`), live gates with WP-CLI `eval-file` and Node + Playwright (from `../layoutlab`, as `verify-pro-switch-design.cjs`).

**Spec:** `docs/superpowers/specs/2026-11-10-pro-lab-design.md` (read it first; its "Findings that change the plan" override the original brief).

## Global Constraints

- Nothing Pro, licence-gated or remote in `wp-plugin/`; the only free change is `StudioStore::linked()` (read-only). `tests/WpOrgComplianceTest.php` is never weakened.
- The validator (`src/`, `wp-plugin/validator/`) is not touched.
- Both features are MCP + REST only for new tools: `lab_restyle` goes into `ProOpenApi::MCP_REST_ONLY`; Pro ChatGPT operations stay 14.
- Every page write goes through `LayoutGate::check( $new, $stored )` and `HistoryService::write( $id, $new, 'lab_restyle' )` (restyle) or the existing `BuildSite` insert path (build); every change is one recorded batch; previews return a single-use `PreviewToken` (30 minutes, user-bound).
- `StudioStore` stays the only code that queries the Studio table; every call passes the brief owner's user id.
- Strict arguments (`Args::*`), never cast; `lab_restyle` takes at most 25 pages (`LabRestyle::MAX_PAGES = 25`).
- Exact guard message: `<tool> needs a newer version of the free plugin "JHMG AI Editor for Divi 5" (one with Divi 5 Lab). Update the free plugin; the other Pro tools keep working.` where `<tool>` is `lab_restyle` or `build_site's brief option`.
- `build_site` callers who pass `content` get byte-identical answers and items; the tool description string of `build_site` is unchanged.
- No version bump, no release, no `readme.txt`/`README.md` edit, no `Compat::MIN_FREE` change, no timing or token claims.
- Suites: `make test` and `make test-pro` green after every task; golden re-freezes only where a task says so (`AIED_UPDATE_GOLDEN=1`), with the diff reviewed.

## Review Focus

Each line also has its test in the owning task.

1. A brief edited in the Lab screen between the preview and the run: the page must be skipped `changed_since_preview` and neither page nor brief touched (Task 5, `testABriefEditedSinceThePreviewIsSkipped`).
2. Undo of the undo: walking the inverse items in the opposite order must put the new look back on page AND brief (Task 5, `testUndoOfTheUndoPutsTheNewLookBackOnPageAndBrief`).
3. An administrator who is not the brief owner runs `undo_batch`: the brief row is restored under the owner's id, never copied to the admin (Task 3, `testAnAdministratorWhoIsNotTheOwnerRestoresUnderTheOwnersId`).
4. A person who already has 45 briefs builds a 10-page site: the 6th brief page is refused before any page is created and no brief is pruned (Task 8, `testAUserAtTheBriefCapIsRefusedBeforeAnythingIsCreatedAndNothingIsPruned`).
5. Hostile words in a brief page (`{{aied:color:accent}}`, `$variable({"type":"content"})$`, `<!-- /wp:divi/section -->`, `"`, `--`, `<script>`): stored literally, no token, marker or block formed, gate clean (Task 7, `testHostileWordsStayLiteralInABriefPage`).
