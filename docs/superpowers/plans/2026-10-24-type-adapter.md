> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A design language also decides the headline type. A recipe `divi/heading` (or an eyebrow `divi/text`) carries `"aied":{"type":"display|title|eyebrow"}`; when the recipe is served, the language's weight, letter spacing and (only when the language asks for capitals) capitalisation for that role are written at the block's proven desktop font path. The data lives on the language (`type` object), is pinned to the language prose and to Divi's own font file, is shown in the language topic and the `typography` topic by GENERATED text, is proven on the real Divi by a probe and a render gate, and 206 headings and labels of the library are migrated.

**Architecture:** The kit-adapter pattern again, but keyed by LANGUAGE, not kit (spec Ruling 1). Probe first (Task 1); language data + validity + proofs (Task 2); a pure `LanguageAdapters` (patch per block/role/language, `TYPE_PROVEN` pinned to the vocabulary table) and a pure `LanguageResolver` (the `KitResolver` scanner discipline, sharing one new helper `BlockAttrs`), run in `SectionRecipes` as ImageTokens -> LanguageResolver -> KitResolver -> RecipeTokens through ONE new public function `SectionRecipes::resolveMarkup()` (Task 3); a golden + sha256 freeze and a pure migration report (Task 4); the recipe migration by a deterministic script (Task 5); a render gate `make verify-language-type` with pure tests and synthetic departures (Task 6); docs (Task 7); controller live gates and the whole-branch review (Task 8). Adapter B (rhythm) gets its own plan later and only ADDS entries to the pieces marked "B adds" below.

## Controller rulings (2026-10-24; WHERE THIS SECTION CONFLICTS WITH THE TEXT BELOW, THIS SECTION WINS)

Restated from the spec; they bind every implementer:
1. **Ruling 1:** type lives on the LANGUAGE (`type` in `wp-plugin/data/design-languages.json`), never on a style kit. No kit file, kit adapter or kit golden changes.
2. **Ruling 2:** three roles only: `display` (recipe h1, h2), `title` (h3), `eyebrow` (h4 in the eyebrow font, an uppercase eyebrow-font text label). The patch writes ONLY `weight`, `letterSpacing` and (see 5) `capitalization`; never size, line height, colour, family, alignment, style, `headingLevel`, or anything outside the two font paths.
3. **Ruling 3:** the marker is exactly `"aied":{"type":"<role>"}` (one key, no `on`, no `ground`); a separate resolver that runs BEFORE the kit step. A type marker never reaches `KitResolver::resolve()`: `resolveMarkup()` returns null if `LanguageResolver::leftovers()` is not empty after the language step.
4. **Ruling 4:** the language wins over a recipe literal at the same key (deep merge, the `KitResolver::merge` semantics). The migration DROPS `weight`, `letterSpacing` and `capitalization` from EVERY breakpoint of every marked block (so a `none` role really shows Divi's default), and every heading or uppercase label NOT marked is a named, shrink-only exemption with a reason.
5. **Capitalisation `none` (source finding, Spec issue 1):** Divi 5.15.1 has NO `capitalization` value `none` (`includes/builder-5/server/Packages/StyleLibrary/Declarations/Font/Font.php` lines 543-561 emit `text-transform` only for `uppercase|lowercase|capitalize`, and `none` only for an empty `''` over an inherited uppercase; `includes/builder-5/server/Migration/FontCapitalizationMigration.php` `CAPITALIZATION_VALUES` lacks `none` and, for blocks with `builderVersion` < 5.8.1 (most recipe blocks), UNSETS it). So a `none` role writes NO capitalisation key. The probe confirms (`lt-heading-caps-none`, `lt-text-caps-none` expect DEAD). If either comes back PASS, STOP: the controller decides.
6. **Ruling 5:** every weight must exist in the role's font according to Divi's OWN `google-fonts.json` (committed as `fixtures/shapes/font-weights.json` by a script); the live code `type-font-loaded` guards the rest.
7. **Ruling 6:** `uppercase` on `display` or `title` only in a language whose own prose asks for capital headlines: the closed, shrink-only list `['brutalist-flat']` in the test.
8. **Ruling 7:** desktop value only. The probe's desktop-only candidates must change the computed style at 900 and 400 px too (`heading-cascade`, `text-cascade`). If a cascade decision is false, the patch writes the same three keys at `desktop`, `tablet` and `phone` (the golden follows); this is the ONLY fallback. Any other false decision makes `typePatch()` return null for that carrier (the marker stays, the recipe is refused, the suite fails loudly): STOP and report.
9. **Ruling 12:** the dogfood scorer is not extended (say so in the Outcome).
10. Visible difference: no two languages share a (display, title, eyebrow) triple. Measured on the amended table: all ten are distinct, so NO exemption file is created (cap 0, asserted).
