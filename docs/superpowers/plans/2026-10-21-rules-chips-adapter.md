# Rules and Chips Adapter Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A style kit also styles the thin things between modules: markers `rule` (quiet) and `rule-strong` on `divi/divider`, `divi/group` and `divi/column`, and `chip` on `divi/group` (a tag) and `divi/icon` (an icon chip), resolved by `KitAdapters`, proven on the real Divi, with the 59 rule blocks (23 recipes) and 14 chip blocks (3 recipes) of the library migrated.

**Architecture:** The forms-adapter pattern again: probe every path ON each carrier first (Task 1); a pure audit of the library and the measured quiet-rule floor (Task 2); new `rulePatch()` / `chipPatch()` branches in `KitAdapters::patch` (button, card, item and form output untouched) with proven-decision constants `RULE_PROVEN` / `CHIP_PROVEN` pinned to the vocabulary tables; resolver roles; pure contrast proofs over every kit x language x band x role; goldens; near-duplicate lists; recipe migration with the merge trap; a render-gate extension; guide wording generated from `KitAdapters::APPLIED` inside the existing `kit-rules` and `controls` topics (no new topic name).

**Tech Stack:** pure PHP 8 (`wp-plugin/src/`), PHPUnit (`make test`), Node + Playwright probe/render scripts against the Docker dev site (Divi 5.15.1).

**Spec:** `docs/superpowers/specs/2026-10-21-rules-chips-adapter-design.md` (approved by delegation 2026-10-21; Rulings 1-7). Templates: `docs/superpowers/plans/2026-10-19-forms-adapter.md` and its spec Outcome (probe-first, `FORM_PROVEN` pinned to a vocabulary table, contrast proof, golden, near-duplicate list, `FormMigrationTest`, render gate), `docs/superpowers/plans/2026-10-19-accordion-adapter.md` (the generated `kit-rules` topic), `docs/superpowers/plans/2026-10-20-image-radius.md` (whole-value kit tokens such as `{{aied:kit:radius-control}}`). Code to mirror: `KitAdapters::formPatch()`, `KitFormAdapterTest`, `KitFormGoldenTest`, `FormMigrationTest`, `ImageRadiusMigrationTest`, `StyleGuideKitRulesTest`, `scripts/lib/kit-form-run.cjs`, `scripts/lib/kit-media-run.cjs`.

Decisions this plan makes where the spec says "Left to the builder" (each is one constant or one sentence; listed again in the spec Outcome by Task 7):
- The topic that teaches `divi/divider` is **`controls`** (`StyleGuide::controlsTopic()`, its "Divider line" section and worked example); it gains one generated sentence `controlsKitSentence()`.
- Constant names `KitAdapters::RULE_PROVEN`, `KitAdapters::CHIP_PROVEN`, `KitAdapters::RULE_COLOUR`; the floor `RuleChipAudit::QUIET_RULE_FLOOR`; test helper `tests/Support/RuleChipAudit.php`.
- Reused as they are: `cardFrameRole()`, `colour()`, `frameStyles()` (for the tag's full frame). Not used: `restShadow()`, `shadow()` (rules and chips take no shadow).
- Chip candidate ids use the prefix **`kch-`**, not `kc-` (the card probe already owns `kc-*` ids: Spec issue 2).
- A library rule's role is decided **by its colour** (`border` or any alpha token -> `rule`; `text`, `inverse`, `bg`, `accent` -> `rule-strong`): 22 quiet, 37 strong (Spec issue 6).
- The icon chip's fill and glyph are ALWAYS written by the kit (deterministic own-ink rule), and on an `accent` band the chip takes the button's accent treatment (fill `surface`, glyph `text`) (Spec issue 8).
- The tag chip's frame colour follows the band (Spec issue 7).
