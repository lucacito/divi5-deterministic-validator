# pro-addon/ — JHMG AI Editor for Divi 5 Pro (separate plugin)

The Pro add-on for the free WordPress.org plugin in `wp-plugin/`. It is a **separate plugin**, sold and hosted at divi5lab.com, never shipped in the free zip and never uploaded to WordPress.org. It extends the free plugin only through the `jhmg_aied_*` hooks (`docs/EXTENDING.md`) and calls a small set of the free plugin's classes (pinned by `tests/FreeApiCompatTest.php`).

Spec: `docs/superpowers/specs/2026-10-02-pro-addon-design.md`. Plans: `docs/superpowers/plans/`.

## Preview tokens

`find_replace_site` and `manage_theme_template` need the token of a dry run of the same arguments (`src/Site/PreviewToken.php`): signed, bound to the arguments, the items' content hashes (or the template's state) and the user who previewed, valid 30 minutes, and spent by the first real run, so an `undo_batch` that puts the previewed content back cannot be followed by a replay. The spent mark is a transient: an object cache that evicts it can make a spent token usable again inside its 30 minutes, for the same user and the same arguments only. A content change since the preview is still caught (the changed-since check), but a replay after an `undo_batch` that restored the previewed content is not; every capability check and `LayoutGate` still run on a replay.

## Known limits

- The audit's link check cannot tell a missing page from an archive or custom route (the finding says so), and reads at most 200 links per item (`LINKS_NOT_ALL_CHECKED`).
- On a site with more than 1000 Divi 5 pages `audit_site` audits the first 1000 (by id) and says so, and `find_replace_site` refuses and asks for `page_ids`.
- The ChatGPT importer allows 30 operations in total: 16 free + 13 Pro = 29, so a 14th Pro operation needs an explicit decision.
- The `verify-pro-*` scripts create and delete throwaway content (`verify-pro-rest` is read-only): all six refuse to run unless the site host is localhost, 127.0.0.1, ::1, `*.local`, `*.test` or `*.localhost` (`scripts/dev-guard.php`).

## Dev override of the licence server

`AIED_PRO_API_BASE` redirects the licence key to another host, so it is honoured only when `wp_get_environment_type()` is `local` or `development`; anywhere else it is ignored and `https://divi5lab.com` is used.

## Undo, in one paragraph

Every Pro write is a batch of items. `undo_batch` restores each item whose target still looks the way the batch left it (the changed-since rule; `force` overrides only that), reports the rest (`changed_since`, `no_undo_point`, `forbidden`, `failed`) and says "fully undone" only when every item restored. Page-content items rely on the free plugin's history (10 snapshots per page), so a very old batch may be only partly undoable. Menu undo restores titles, links, nesting, classes, target, title attribute, XFN and description, not custom meta added by other plugins. Header/footer and template items re-check, at undo time, that the layout or template is still a live Theme Builder one, the user's Theme Builder permission and `edit_theme_options`; a change made in Divi's own builder afterwards is never overwritten. Known limitation (free plugin 4.4.0 and older): the dashboard 'recent versions' list also shows header/footer edits made by these tools, but its Restore button only works for pages; free 4.5.0 hides those rows. Undo a header or footer change with `undo_batch`.

## `staged-4.3.0/`

The `src` and `tests` files are verbatim copies of the 4.4.0-tree files for header/footer editing. `4.3.0-free-plugin.diff` is the original 4.3.0 merge diff (837b712), whose handler and guide hunks predate the 4.4.0 edits to the same files; the free re-cut's own removal commits (5cf40c0, fd4e50d, cd5fffe) are the exact current removal hunks. Not run, not shipped. `ThemeLayouts` and the layout half of `EditTarget` were ported into `src/ThemeBuilder/` in 0.3.0; this folder stays as the record of the 4.3.0 spike.

## Contract

It must not need any change to the free plugin beyond the documented hooks. Nothing here is ever loaded by the free plugin's zip, and `phpunit.xml` at the repo root never scans this folder.
